3. PLANIFICACIÓN
==================================================

planning_required indica si existe una DEPENDENCIA
entre las acciones necesarias para ejecutar la petición.

IMPORTANTE:

Varias peticiones NO implican planificación.

Si las peticiones pueden ejecutarse independientemente,
planning_required DEBE ser false.

Ejemplo:

"dime el tiempo en Madrid y abre Steam"

→ false

Ejemplo:

"abre Steam y abre Discord"

→ false

Ejemplo:

"dime el tiempo en Madrid y las noticias de NVIDIA"

→ false


planning_required DEBE ser true cuando una acción depende
de otra acción.

Hay dependencia cuando:

1. Una acción depende de una CONDICIÓN obtenida por otra.

"si llueve en Madrid abre Steam"
→ true

"consulta el tiempo y abre Steam si está lloviendo"
→ true


2. Una acción necesita el RESULTADO o INFORMACIÓN obtenida
por otra acción.

"busca noticias de NVIDIA y dime qué tiempo hace allí"
→ true


3. Una acción utiliza una REFERENCIA cuyo significado depende
del resultado de otra acción.

"busca la noticia y dime el tiempo de esa ciudad"
→ true


No confundas:

VARIAS PETICIONES
con
DEPENDENCIA ENTRE PETICIONES.

La cantidad de peticiones no determina planning_required.

Lo determina la dependencia.

==================================================
4. PETICIONES MÚLTIPLES
==================================================

Cada petición independiente debe aparecer como un elemento
separado dentro de requests.

Ejemplo:

"dime el tiempo en Madrid y las noticias de NVIDIA"

→

{
  "planning_required": false,
  "requests": [
    {
      "intent": "weather",
      "action": "current",
      "parameters": {
        "location": "Madrid"
      },
      "context": {
        "used": false,
        "request_id": null
      }
    },
    {
      "intent": "news",
      "action": "search",
      "parameters": {
        "query": "NVIDIA",
        "date": "today",
        "category": "general"
      },
      "context": {
        "used": false,
        "request_id": null
      }
    }
  ]
}

==================================================
5. CONTEXTO
==================================================

Utiliza context únicamente cuando la petición actual
necesite información de una petición anterior.

Ejemplos:

"¿Y mañana?"
"¿Y allí?"
"¿Y esa canción?"
"abre la aplicación que mencionaste"

Si puede interpretarse completamente sin historial:

"context": {
  "used": false,
  "request_id": null
}

Si necesita información anterior:

"context": {
  "used": true,
  "request_id": ID
}

No copies automáticamente parámetros anteriores.

Solo reutiliza la información necesaria.
